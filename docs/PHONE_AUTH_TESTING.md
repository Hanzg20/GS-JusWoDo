# 📱 手机号登录测试指南

## 🎯 测试步骤

### 步骤 1: 配置 Supabase (生产环境)

如果要在生产环境使用，请按照 [PHONE_AUTH_SETUP.md](./PHONE_AUTH_SETUP.md) 完成 Twilio 配置。

---

### 步骤 2: 开发环境测试（无需 Twilio）

在**开发环境**，Supabase 提供了测试模式，可以**不配置 Twilio** 直接测试：

#### 2.1 启用 Phone Auth（Dashboard）
1. 进入 Supabase Dashboard → **Authentication** → **Providers**
2. 找到 **Phone** 部分
3. 启用 **Enable Phone Sign-up**
4. **不填写** Twilio 凭证
5. 点击 **Save**

#### 2.2 使用测试手机号
Supabase 在开发模式下会自动接受特定格式的测试号码：

```typescript
// 测试手机号格式
+1234567890  // 任何以 +1234567890 开头的号码都是测试号码
```

#### 2.3 查看验证码（Dashboard）
1. 尝试登录时，发送验证码到测试号码
2. 进入 Supabase Dashboard → **Authentication** → **Logs**
3. 查找最新的 `phone_verification` 事件
4. 点击查看详情，可以看到生成的 OTP 验证码

---

### 步骤 3: 前端测试

#### 3.1 启动开发服务器
```bash
npm run dev
```

#### 3.2 访问登录页面
```
http://localhost:5173/login
```

#### 3.3 测试手机号登录
1. 点击 **"手机号"** 标签
2. 输入测试号码（会自动格式化）:
   ```
   +1 (234) 567-8901
   ```
3. 点击 **"发送验证码"**

#### 3.4 查看验证码
**方法 1**: 查看浏览器控制台（如果配置了调试模式）

**方法 2**: 查看 Supabase Dashboard Logs

**方法 3**: 如果配置了 Twilio，检查手机短信

#### 3.5 输入验证码并登录
1. 输入6位验证码（例如：`123456`）
2. 点击 **"确认登录"**
3. 成功后会跳转到首页

| 测试用例 | 输入 | 预期结果 |
|---------|------|---------|

## 🐛 故障排查

### 问题 1: "SMS could not be sent"

**原因**: Supabase 未配置 Twilio

**解决**:
- **开发环境**: 使用测试号码 `+1234567890`
- **生产环境**: 按照 [PHONE_AUTH_SETUP.md](./PHONE_AUTH_SETUP.md) 配置 Twilio

---

### 问题 2: 收不到验证码（生产环境）

**检查步骤**:
1. 确认 Twilio 账号余额充足
2. 检查 Twilio Console → SMS Logs 查看发送状态
3. 确认手机号格式正确（必须是 `+1XXXXXXXXXX`）
4. 检查 Supabase Dashboard → Authentication → Logs 查看错误

---

### 问题 3: "Rate limit exceeded"

**原因**: 发送太频繁

**解决**:
- 等待60秒后重试
- 检查 Supabase Rate Limits 配置是否过于严格

---

### 问题 4: 验证码错误

**原因**:
- 输入的验证码不正确
- 验证码已过期（60秒）
- 使用了旧的验证码

**解决**:
1. 从 Supabase Dashboard Logs 获取最新的验证码
2. 确保在60秒内输入
3. 如果过期，点击"重新发送"
